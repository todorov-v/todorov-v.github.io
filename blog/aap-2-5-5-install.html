Install Ansible Automation Platform 2.5.5

High-level notes for installing Red Hat Ansible Automation Platform 2.5.5 using the bundled installer: prerequisites, inventory, setup and basic post-install checks.

1) Prerequisites & Planning

  • Valid Red Hat subscription for Ansible Automation Platform.
  • Supported RHEL version for AAP 2.5.5 (typically RHEL 8 or 9).
  • DNS records and reverse DNS for nodes.
  • SSH access from installer node to all target nodes.
  • Enough CPU/RAM/disk according to the chosen topology (single node / multi-node).

Recommended: keep at least one separate node as the “installer/control” machine, even in small labs.

2) Download the Bundle

From the Red Hat Customer Portal:

  1. Navigate to Downloads → Red Hat Ansible Automation Platform.
  2. Download the bundle installer for 2.5.5 (offline content included).
  3. Copy the tarball to your installer node.
# On installer node
tar -xvf ansible-automation-platform-setup-bundle-2.5.5-*.tar.gz
cd ansible-automation-platform-setup-bundle-2.5.5-*/

3) Prepare the Inventory

The inventory file controls which components are installed where.

Simple all-in-one example:

[automationcontroller]
aap-controller.example.local

[automationhub]
aap-hub.example.local

[database]
aap-db.example.local

[all:vars]
admin_password=<StrongPassword>
pg_host=aap-db.example.local
pg_password=<DBPassword>
pg_database=awx
pg_username=awx

For a real environment, separate controller, hub and database, and align with official sizing guidelines.

4) Run the Installer

Once the inventory is ready and SSH connectivity is verified:

# Optional: check connectivity
ansible -i inventory all -m ping

# Run the installer
./setup.sh
  • Installer will configure repositories, database, controller, hub, and EEs.
  • Watch for failed tasks and fix issues (DNS, subscription, SELinux, firewalld).

5) Post-Install Checks

  • Access the web UI for Automation Controller (URL from installer output).
  • Log in with the admin user and the password from inventory.
  • Verify that:
    • Projects can sync (Git, etc.).
    • Credentials can be created.
    • Inventory sync works and hosts show up correctly.
    • Job templates can run simple playbooks successfully.

6) Common Issues & Tips

  • Subscription issues: make sure the host is registered with Red Hat and has AAP entitlements.
  • DNS/SSL problems: ensure FQDNs and certificates match; avoid using raw IPs.
  • Firewall: open required ports (HTTP/HTTPS, DB where needed) or use firewalld rules from the docs.
  • Re-running setup: small changes in the inventory can usually be applied by re-running setup.sh, but for major topology changes follow official guidance.

For production, also plan:

  • External database (managed or hardened internal).
  • Backups for controller and database.
  • Integration with LDAP/SSO.
  • Execution Environments registry strategy.

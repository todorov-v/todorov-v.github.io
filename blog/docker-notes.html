General Docker Notes — Build, Deploy, Troubleshoot

A concise, practical memo for daily Docker work: images, containers, logs, networking, and debugging.

1) Building Images

  • Use a small base image (e.g. alpine or debian:bookworm-slim).
  • Pin versions for repeatable builds.
  • Use multi-stage builds for smaller production images.
docker build -t myapp:1.0 .
docker images

Example multi-stage build:

FROM node:20-alpine AS build
WORKDIR /app
COPY . .
RUN npm ci && npm run build

FROM nginx:1.27-alpine
COPY --from=build /app/dist/ /usr/share/nginx/html
EXPOSE 80

2) Running & Deploying Containers

docker run -d --name web -p 8080:80 org/myapp:1.0
docker exec -it web /bin/sh
docker logs -f web

Compose example:

version: "3.9"
services:
  web:
    image: org/myapp:1.0
    ports: ["8080:80"]
    depends_on: ["db"]
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: secret

3) Networking & Volumes

docker network create app-net
docker run -d --network app-net --name web org/myapp:1.0
docker volume ls
docker volume inspect pgdata
  • Use custom bridge networks for inter-container DNS.
  • Use volumes for persistent data.

4) Troubleshooting Tips

  • Use docker ps, logs, inspect for diagnostics.
  • Run docker exec -it container /bin/sh to debug interactively.
  • Verify port mappings with docker port.
  • Use docker system prune to clean unused data.

5) Security & Maintenance

  • Rebuild images regularly to patch base image CVEs.
  • Use HEALTHCHECK and resource limits (--memory, --cpus).
  • Avoid running as root inside containers.
  • Tag images semantically and avoid latest in production.

VMware Aria Day-2 Operations — Start, Stop, Update

Practical guide for managing Day-2 lifecycle actions in Aria Automation (vRA): built-in, custom, and API-driven workflows.

1) Built-in Actions

  • Start, Stop, Reboot, Suspend — directly on VM resources.
  • Change CPU, RAM, or Disk through “Update” actions (if policy allows).
  • Control visibility and access with Service Broker entitlements.

2) Custom Actions (ABX / Orchestrator)

For advanced scenarios, create custom Day-2 actions via ABX (Python/Node) or Orchestrator workflows.

# ABX Python example
def handler(context, inputs):
    vm_id = inputs.get("resourceId")
    return {"message": f"PowerOn initiated for {vm_id}"}
  • ABX — quick, serverless integrations (REST, CMDB, tags).
  • Orchestrator — complex vSphere automations and approvals.

3) Using the API

Day-2 actions are available via REST API. Example flow:

# Get VM resourceId
GET /iaas/api/machines?filter=name eq 'vm01'

# List available actions
GET /deployment/api/deployments/{deploymentId}/resources/{resourceId}/actions

# Invoke an action
POST /deployment/api/deployments/{deploymentId}/resources/{resourceId}/requests
{
  "actionId": "PowerOn",
  "inputs": {}
}

4) Update Operations

  • Scale up/down CPU or memory.
  • Resize disks or add new ones.
  • Modify tags, metadata, or network assignments.
{
  "actionId": "UpdateMachine",
  "inputs": {
    "cpuCount": 4,
    "memoryInMB": 8192
  }
}

5) Governance & Policies

  • Custom forms to show only approved parameters.
  • Approval policies for high-impact updates.
  • Event subscriptions for pre/post hooks.

6) Best Practices

  • Restrict Day-2 actions per project/role.
  • Automate approvals for repeatable changes.
  • Monitor with Activity logs or export to SIEM.
  • Integrate with Aria Operations for visibility.
